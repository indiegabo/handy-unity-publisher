Recovery Paths

Diagnose the host before you widen the blast radius.

HGP is local-first, so most failures come from host capabilities, credentials, or project configuration rather than remote shell state. Use Settings as the first inspection surface and change one variable at a time.

Unity detection

  • Confirm the required Unity editor is installed on the same host where HGP runs.
  • Reopen the project detail surface and validate the Unity executable or detected version.
  • If the wrong editor is discovered, correct the project-level build target configuration before retrying.

Repository authentication

  • Use Settings to inspect the connected GitHub login or reusable repository credential state.
  • Refresh the credential if status reports missing keys or stale metadata.
  • Run a manual repository inspection before assuming polling or release automation is broken.

Runtime health and directories

Logs

Open the runtime log path from Settings when the shell reports an unhealthy or stopped runtime state.

Artifacts and runs

Use the runtime directories panel to inspect artifacts, retained logs, and run outputs before re-queuing work blindly.

Localization root

Additional locale files belong in the localization root next to the packaged shell resources. Invalid JSON packs are ignored and surfaced as warnings.

Itch publication prerequisites

  • The reusable Itch credential is ready in Settings.
  • The packaged shell includes the Butler sidecar expected by the publish flow.
  • The target destination metadata still matches the upstream Itch project and channel.
