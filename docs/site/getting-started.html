First Run

Install the beta and confirm the runtime is actually healthy.

The Windows beta ships as a packaged desktop shell with bundled runtime sidecars and install-root localization files. Your first goal is not to create a project immediately. It is to confirm that the shell, runtime, and host prerequisites are aligned.

Windows installation checklist

  1. Run the current HGP Windows installer and finish the normal setup flow.
  2. Launch HGP from the Start menu or desktop shortcut.
  3. Confirm the tray icon appears and the compact shell window opens.
  4. Open Settings and verify the shell version and bundled runtime version are populated.
  5. Check the runtime badge. Healthy means the local supervisor booted correctly.

What healthy first launch looks like

Tray-resident shell

Closing the window hides it back to the tray. This is expected. Use the tray icon or tray menu to reopen the shell.

Stable runtime status

The shell remains useful only when the bundled runtime is healthy. Use Settings to open logs and runtime directories if status drifts.

Actionable settings

Settings is where you inspect version metadata, runtime paths, localization preferences, and reusable credentials.

Automation posture

HGP separates runtime health from automation posture. Active allows automatic intake. Idle keeps the runtime and workers alive but stops automatic polling intake until you deliberately switch back.

  • Use Active when the workstation should keep monitoring configured repositories.
  • Use Idle when you want the runtime alive but do not want fresh polling work to queue automatically.
  • Manual operator-driven actions remain the preferred recovery path while Idle is active.

Host prerequisites to verify early

  • Unity editors required by your projects are installed locally.
  • Git access is available for any repository projects you plan to connect.
  • Itch publication hosts have Butler prerequisites available when you intend to publish there.
  • The operator account can read and write the HGP app data directory.

Storage roots during development

Development builds keep their persistent runtime data under the same host-specific root, but the product directory name is suffixed with _DEV so sandbox state does not collide with production.
