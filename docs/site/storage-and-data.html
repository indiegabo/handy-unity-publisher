Storage Contract

Know exactly where HGP writes runtime data on each host.

HGP keeps durable runtime data under one host-owned application data root per user. Production builds use HandyGamesPublisher and development builds suffix that directory with _DEV to keep sandbox data isolated.

Host roots

Windows

Production: %LOCALAPPDATA%/HandyGamesPublisher/runtime

Development: %LOCALAPPDATA%/HandyGamesPublisher_DEV/runtime

macOS

Production: ~/Library/Application Support/HandyGamesPublisher/runtime

Development: ~/Library/Application Support/HandyGamesPublisher_DEV/runtime

Linux

Production: $XDG_DATA_HOME/HandyGamesPublisher/runtime or ~/.local/share/HandyGamesPublisher/runtime

Development: $XDG_DATA_HOME/HandyGamesPublisher_DEV/runtime or ~/.local/share/HandyGamesPublisher_DEV/runtime

What lives in the runtime tree

  • state/runtime.db stores durable workflow metadata and queue state.
  • state/*.json files store health, supervision, and recovery snapshots.
  • logs/runtime.jsonl stores operator-facing runtime traces.
  • artifacts/ stores produced build and publish outputs.
  • runs/ stores execution-local scratch data and run workspaces.

What does not belong there

  • Installer binaries live under the host application location, not inside the runtime state tree.
  • Large blob payloads do not belong in SQLite.
  • Roaming preferences stay small and user-centric; the runtime root stays operational and host-local.
  • LocalLow is not part of the default storage contract for HGP.
