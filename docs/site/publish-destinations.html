Reusable Credentials

Configure publish destinations once, then reuse them deliberately.

The beta already supports Itch credential authoring inside the app. Settings acts as the shared inventory so destination-level publish flows can bind to reusable credentials rather than duplicating secrets across every project.

Prepare credentials in Settings first

  1. Open Settings.
  2. Create a reusable Itch credential or repository credential from the credential inventory panel.
  3. Confirm the credential summary reports a healthy or ready state.
  4. Return to the project detail surface and bind the credential where needed.

Itch publish destination flow

Runtime prerequisite

Butler sidecars must be present in the packaged shell. Release bundles stage the expected binary alongside the runtime sidecar.

Credential binding

Bind the reusable Itch credential from settings instead of rewriting the API key for every destination.

Output checks

Verify the build output exists before you expect the publish run to succeed. Publish destinations do not replace build validation.

Healthy publish setup checklist

  • The project has at least one successful build target configured.
  • The destination points to the correct Itch channel or remote endpoint.
  • The reusable credential is ready and bound to the destination.
  • The operator can inspect logs and retained outputs if the publish step fails.

When publication fails

Open the execution report, build logs, and runtime logs before changing multiple variables at once. Most publication failures come from missing artifacts, stale credentials, or destination metadata that no longer matches the upstream service.
