Manual Source Mode

Register a local Unity workspace and release it from the app.

The beta supports Unity projects that live only on the local filesystem. This is the path for prototypes, internal branches, or workspaces that are not yet mirrored to a remote Git repository.

When to use local workspace mode

Good fit

The Unity project already lives on disk, you can build it locally, and you want HGP to standardize build and publish execution.

Current beta posture

Treat local workspaces as deliberate operator-driven release flows. Manual dispatch is the safe baseline for this source mode.

Same downstream surfaces

Build targets, outputs, and publish destinations stay shared with repository projects rather than fragmenting into a second stack.

Local workspace onboarding flow

  1. Create a new project from the Projects screen.
  2. Select the local workspace source mode.
  3. Choose the Unity workspace directory on disk.
  4. Define the same build targets and publish destinations you would use for a repository project.
  5. Save the project and reopen its detail view to confirm source settings and targets look correct.
  6. Dispatch a manual release and inspect outputs before treating the workstation flow as stable.

Validate the workspace before the first release

  • The chosen folder is the Unity project root, not a parent workspace directory.
  • Required Unity editor versions are installed on the host.
  • Output paths are writable by the operator account.
  • Any downstream publish credentials are already saved and healthy in Settings.

What to inspect after the run

After a manual local release, inspect build history, artifact records, runtime logs, and any publish step detail before you trust the workstation loop as a repeatable path.
